# Handoff

Файл содержит актуальный контекст для продолжения работы в новой сессии. Его нужно полностью обновлять по запросу пользователя `сохрани сессию` или `bfe`, а также при любом запросе сохранить контекст перед сменой сессии.

Обновлено 23 ноября 2026 года.

## Как обновлять файл

Перед обновлением нужно проверить фактическое состояние файлов, статусы задач, результаты последних проверок и незавершённую работу. Новый снимок должен содержать текущее состояние, выполненные работы, незавершённую работу, следующие действия, блокировки, принятые решения, результаты проверок и ссылки на все нужные файлы.

При обновлении нужно проверить [спецификацию](Retro_Spec.md), [план](tasks.md), [README](../README.md) и [AGENTS.md](../AGENTS.md) на непротиворечивость, полноту и актуальность. Найденные расхождения нужно исправить или явно записать, если требуется решение пользователя.

## Текущее состояние

Этапы с M0 по M7 завершены и отмечены в [плане](tasks.md). Реализованы основа приложения, встречи, приглашения, SignalR, присутствие, роль фасилитатора, карточки, приватность, готовность, группировка, голосование, обсуждение и таймер только в памяти процесса. Следующий этап — M8: порт Jira и тестовый экспорт задач.

Последний коммит `eb17458 Implement M6 discussion and action items`. Код и тесты M7, обновления плана, README и этого handoff пока не закоммичены. Пользователь просил коммит только для M6.

Docker отсутствует и для проверок не используется. .NET SDK 10.0.404 находится в `/usr/local/share/dotnet`, настройка `PATH` описана в [README](../README.md#подготовка-инструментов).

## Что уже сделано

- Встречи, настройки Draft, шаблоны, приглашения, доступ, SignalR, присутствие, исключение, передача роли и перевыборы работают на реальной SQLite.
- Карточки, персональная приватность, готовность, группы и локальная заглушка внутреннего ИИ работают. Ручная группировка доступна при отключённой заглушке.
- Голосование создаёт темы при `Group → Vote`, рассчитывает бюджет, поддерживает позднее вступление, версии бюллетеней, открытый и анонимный расклад и атомарное изменение лимита.
- Обсуждение фиксирует очередь при `Vote → Discuss`, поддерживает общую текущую тему, статусы и возврат к пропущенным. Комментарии, решения и задачи независимы и имеют отдельные таблицы, API и UI.
- Задачи сохраняют исторического исполнителя после исключения. Новое назначение исключённому запрещено. `exportStatus` пока `notExported`, реальный экспорт относится к M8.
- [TimerContracts](../src/Application/TimerContracts.cs) описывает `MeetingTimer`, результаты команд и порт `IMeetingTimer`.
- [InMemoryMeetingTimer](../src/Infrastructure/Timers/InMemoryMeetingTimer.cs) хранит один текущий запуск на встречу только в памяти: фазу, `runId`, `endsAtUtc`, команды дедупликации и очередь истёкших запусков. Состояние защищено блокировкой, параллельные `start` создают только один запуск.
- Повтор команды с тем же `operationId` и отпечатком возвращает прежний результат. Другое тело даёт `OperationConflict`. Дедупликация не записывается в `command_deduplication` или другие таблицы.
- `add` продлевает текущий `endsAtUtc`. `stop` и смена фазы отменяют запуск без сигнала. Добавление после фактического истечения возвращает конфликт, новый запуск после истечения разрешён.
- [TimerWorker](../src/Infrastructure/Background/TimerWorker.cs) извлекает истёкшие запуски и публикует один `TimerExpired(runId, phase)` через SignalR. Повторное чтение состояния не дублирует событие.
- [TimerService](../src/Application/TimerService.cs) проверяет фасилитатора, фазу, положительную длительность и гонку со сменой фазы. [TimerEndpoints](../src/Api/TimerEndpoints.cs) добавляет `POST timer/start`, `timer/add` и `timer/stop`.
- [MeetingBoardService](../src/Application/MeetingBoardService.cs) отменяет таймер после успешного перехода фазы. Будущее завершение M9 также должно отменить таймер.
- [MeetingSyncService](../web/src/app/meeting-sync.service.ts) вычисляет поправку часов по `serverNowUtc`, обновляет отсчёт каждую секунду, показывает «Время вышло» и не получает старые события после reconnect.
- [TimerSoundService](../web/src/app/timer-sound.service.ts) создаёт `AudioContext` только по пользовательскому жесту. Web Locks и маркер `runId` в `localStorage` обеспечивают один звук на браузерный профиль. При запрете звука остаётся визуальное оповещение.
- Экран встречи поддерживает запуск, добавление, остановку, проверку звука и скрытие визуального оповещения.
- Миграций M7 нет. Состояние и история таймера исчезают при новом экземпляре приложения.
- Переход из Discuss в Closed временно возвращает `CompletionUnavailable` до реализации M9.

## Проверки

Последняя полная проверка прошла успешно:

- `dotnet restore`, `dotnet build` и полный `dotnet test` прошли без предупреждений компилятора. Всего 71 backend-тест: Domain 25, Application 8, Infrastructure 6 и API 32.
- `npm ci`, production build без предупреждений и 10 unit-тестов frontend прошли.
- Все семь E2E [M1](../web/e2e/m1.spec.ts), [M2](../web/e2e/m2.spec.ts), [M3](../web/e2e/m3.spec.ts), [M4](../web/e2e/m4.spec.ts), [M5](../web/e2e/m5.spec.ts), [M6](../web/e2e/m6.spec.ts) и [M7](../web/e2e/m7.spec.ts) прошли на реальных SPA, API, SQLite и WebSocket.
- [InMemoryMeetingTimerTests](../tests/Infrastructure.Tests/InMemoryMeetingTimerTests.cs) проверяют повторы, конфликт тел команд, параллельные запуски, продление, остановку, однократное истечение и потерю состояния в новом экземпляре.
- [TimerApiTests](../tests/Api.Tests/TimerApiTests.cs) проверяют права и фазы, общий снимок, идемпотентность, отсутствие таблиц и записей таймера в БД, SignalR-истечение, отмену при смене фазы и рестарт с той же SQLite.
- E2E M7 использует два независимых контекста и вторую вкладку фасилитатора. Проверены отсчёт, добавление, остановка без сигнала, визуальное истечение, новый запуск, отмена при переходе и отсутствие старого оповещения в новой вкладке.
- Звук в E2E заменён счётчиком через тестовый `AudioContext`. Две вкладки одного профиля дали ровно один сигнал, второй профиль — свой один сигнал.

`npm audit` сообщает о четырёх предупреждениях в optional-цепочке `ng-morph` и `minimatch`. Принудительный override не применялся. Открыта задача M10.8.

## Принятые решения

- MVP включает полную встречу до Closed и PDF. Production-интеграции, PostgreSQL-приёмка, Kubernetes, GitLab CI, Sage и нагрузочный тест относятся к итоговой поставке.
- Временное хранение MVP использует SQLite. Проверки SQLite не заменяют проверки PostgreSQL.
- Таймер полностью хранится в памяти процесса, включая `runId`, срок окончания и дедупликацию команд. В БД нельзя сохранять никакие данные таймера. После рестарта приложения таймер и история команд отсутствуют.
- Решения и комментарии являются разными сущностями. Для каждой нужны свои хранение, API, UI и представление в итогах и PDF.
- Сотрудник, который вступил во время Vote, получает полный текущий бюджет голосов.
- Внутренний ИИ пока заменён локальной заглушкой за портом `IGroupSuggestionProvider`. Корпоративный контракт, адрес и схему аутентификации нельзя выдумывать.
- TWork, Jira и Sage сначала получают порты и dev-адаптеры. Корпоративный Jira пока не имеет предоставленного контракта, поэтому M8 реализует только порт и тестовый адаптер.

## Конфигурация заглушки

`Integrations__Ai__Enabled` управляет заглушкой. В Development и Testing она включена, в основном `appsettings.json` выключена. Состояние доступно в снимке как `integrations.ai`. При отключении API возвращает `IntegrationUnavailable`, а UI оставляет ручную группировку.

## Незавершённая работа

M7 завершён и проверен, но не закоммичен. Незавершённой реализации внутри M7 не осталось. M8 ещё не начат: порт экспорта, состояние намерения, тестовый адаптер и обработка неизвестного исхода не реализованы.

При реализации M9 нужно удалить записи `command_deduplication`, которые могут связать сотрудника с карточкой, одновременно с удалением `card_authors` при `anonymousCards=true`. При `anonymousVotes=true` нужно физически удалить индивидуальные голоса и версии `personal_ballots`, сохранив суммы. Эти требования записаны в M9.3.

## Состояние документации

[Спецификация](Retro_Spec.md) соответствует принятым решениям: таймер только в памяти, решения и комментарии раздельны, поздний участник Vote получает полный бюджет. [План](tasks.md), [README](../README.md) и [AGENTS.md](../AGENTS.md) соответствуют текущей реализации. Открытых противоречий между документами не выявлено.

Для M8 есть ограничение: корпоративный контракт Jira не предоставлен. Нельзя придумывать URL, проект, маппинг пользователей, заголовки или схему аутентификации. Тестовый адаптер должен явно отличаться от production-интеграции.
