# Handoff

Файл содержит актуальный контекст для продолжения работы в новой сессии. Его нужно полностью обновлять по запросу пользователя `сохрани сессию` или `bfe`, а также при любом запросе сохранить контекст перед сменой сессии.

Обновлено 23 ноября 2026 года.

## Как обновлять файл

Перед обновлением нужно проверить фактическое состояние файлов, статусы задач, результаты последних проверок и незавершённую работу. Новый снимок должен содержать текущее состояние, выполненные работы, незавершённую работу, следующие действия, блокировки, принятые решения, результаты проверок и ссылки на все нужные файлы.

При обновлении нужно проверить [спецификацию](Retro_Spec.md), [план](tasks.md), [README](../README.md) и [AGENTS.md](../AGENTS.md) на непротиворечивость, полноту и актуальность. Найденные расхождения нужно исправить или явно записать, если требуется решение пользователя.

## Текущее состояние

Этапы с M0 по M6 завершены и отмечены в [плане](tasks.md). Реализованы основа приложения, встречи, приглашения, SignalR, присутствие, роль фасилитатора, карточки, приватность, готовность, группировка, голосование и обсуждение с отдельными решениями, комментариями и задачами. Следующий этап — M7: таймер только в памяти процесса.

Последний коммит `9acc0bd Implement M5 voting`. Код и тесты M6, обновления спецификации, плана, README и этого handoff пока не закоммичены. Пользователь просил коммит только для M5.

Docker отсутствует и для проверок не используется. .NET SDK 10.0.404 находится в `/usr/local/share/dotnet`, настройка `PATH` описана в [README](../README.md#подготовка-инструментов).

## Что уже сделано

- Созданы семь SQLite-миграций. [0006_voting.sql](../src/Infrastructure/Persistence/Migrations/SQLite/0006_voting.sql) добавляет голосование, [0007_discussion.sql](../src/Infrastructure/Persistence/Migrations/SQLite/0007_discussion.sql) — очередь обсуждения, текущую тему, комментарии, решения и задачи. Таблиц и полей таймера в БД нет.
- Встречи, настройки Draft, шаблоны, приглашения, доступ, SignalR, присутствие, исключение, передача роли и перевыборы работают на реальной SQLite.
- Карточки, персональная приватность, готовность, группы и локальная заглушка внутреннего ИИ работают. Ручная группировка доступна при отключённой заглушке.
- При переходе `Group → Vote` создаются темы и бюллетени, фиксируется `N`. Голосование поддерживает бюджеты, позднее вступление, версии бюллетеней, открытый и анонимный расклад и атомарное изменение лимита.
- [Discussion](../src/Domain/Discussion.cs) содержит отдельные модели `DiscussionTopic`, `TopicComment`, `TopicDecision` и `ActionItem`. [DiscussionQueue](../src/Domain/Discussion.cs) сортирует по убыванию голосов, порядку колонки и строковому стабильному ID, сохраняя нулевые темы.
- При переходе `Vote → Discuss` [SqliteMeetingRepository](../src/Infrastructure/Persistence/Sqlite/SqliteMeetingRepository.cs) в той же транзакции создаёт всю очередь и выбирает первую тему. На пустой доске очередь пуста, текущей темы нет.
- [SqliteDiscussionRepository](../src/Infrastructure/Persistence/Sqlite/SqliteDiscussionRepository.cs) реализует выбор любой темы, статусы `pending`, `discussed`, `skipped`, команду «Далее», возврат к пропущенным и повторное открытие темы.
- `PUT discussion/current` и `PUT topics/{id}/status` изменяют общее для клиентов состояние. `advance=true` разрешено только для текущей темы; после последней темы текущий ID становится `null`, любую тему можно выбрать снова.
- Комментарии и решения имеют независимые таблицы, порты, API и UI. Создание поддерживает `operationId` и дедупликацию без сохранения текста в отпечатке. Изменение и удаление доступны только фасилитатору в `Discuss`.
- Задачи содержат текст и nullable `assigneeId`. Назначить можно только действующего участника. После исключения назначение сохраняется, редактирование текста с тем же историческим исполнителем разрешено, новое назначение исключённому отклоняется.
- [DiscussionService](../src/Application/DiscussionService.cs) и [DiscussionEndpoints](../src/Api/DiscussionEndpoints.cs) реализуют команды M6 и уведомления SignalR после commit.
- [Страница встречи](../web/src/app/meeting-settings-page.ts) показывает рейтинг, текущую тему и её карточки, решения, комментарии, задачи, исполнителей и статусы экспорта. Участник без роли фасилитатора имеет только чтение.
- `exportStatus` локальной задачи пока равен `notExported`; реальный экспорт Jira относится к M8.
- Данные обсуждения читаются только в фазе `Discuss`, без дополнительных запросов на более ранних фазах. Это сохраняет прежнее быстродействие обработчиков присутствия и перевыборов.
- Переход из Discuss в Closed временно возвращает `CompletionUnavailable` до реализации M9.

## Проверки

Последняя полная проверка прошла успешно:

- `dotnet restore`, `dotnet build` и полный `dotnet test` прошли без предупреждений компилятора. Всего 64 backend-теста: Domain 25, Application 8, Infrastructure 2 и API 29.
- `npm ci`, production build без предупреждений и 9 unit-тестов frontend прошли.
- Все шесть E2E [M1](../web/e2e/m1.spec.ts), [M2](../web/e2e/m2.spec.ts), [M3](../web/e2e/m3.spec.ts), [M4](../web/e2e/m4.spec.ts), [M5](../web/e2e/m5.spec.ts) и [M6](../web/e2e/m6.spec.ts) прошли на реальных SPA, API, SQLite и WebSocket.
- [DiscussionQueueTests](../tests/Domain.Tests/DiscussionQueueTests.cs) проверяют голоса, колонки, стабильный ID, нулевые и пустую очередь.
- [DiscussionApiTests](../tests/Api.Tests/DiscussionApiTests.cs) проверяют порядок 2, 2 и 0, общую навигацию, права, возврат к пропущенным, CRUD, дедупликацию, раздельные таблицы и исторического исполнителя.
- E2E M6 использует два независимых контекста. Проверены пропуск первой темы, обсуждение второй, нулевая третья, редактирование решения, комментария и задачи, задачи с исполнителем и без, read-only у участника и возврат к пропущенной.
- Старый тест перевыборов нестабилен при параллельном прогоне: он переводит часы сразу после отключения, пока обработчик ещё читает состояние. Лишние запросы обсуждения вне `Discuss` удалены, логика и тест перевыборов не менялись. После этого полный backend-набор прошёл.

`npm audit` сообщает о четырёх предупреждениях в optional-цепочке `ng-morph` и `minimatch`. Принудительный override не применялся. Открыта задача M10.8.

## Принятые решения

- MVP включает полную встречу до Closed и PDF. Production-интеграции, PostgreSQL-приёмка, Kubernetes, GitLab CI, Sage и нагрузочный тест относятся к итоговой поставке.
- Временное хранение MVP использует SQLite. Проверки SQLite не заменяют проверки PostgreSQL.
- Таймер будет полностью храниться в памяти процесса, включая `runId`, срок окончания и дедупликацию команд. В БД нельзя сохранять никакие данные таймера. После рестарта приложения таймер отсутствует.
- Решения и комментарии являются разными сущностями. Для каждой нужны свои хранение, API, UI и представление в итогах и PDF.
- Сотрудник, который вступил во время Vote, получает полный текущий бюджет голосов.
- Внутренний ИИ пока заменён локальной заглушкой за портом `IGroupSuggestionProvider`. Корпоративный контракт, адрес и схему аутентификации нельзя выдумывать.
- TWork, Jira и Sage сначала получают порты и dev-адаптеры.

## Конфигурация заглушки

`Integrations__Ai__Enabled` управляет заглушкой. В Development и Testing она включена, в основном `appsettings.json` выключена. Состояние доступно в снимке как `integrations.ai`. При отключении API возвращает `IntegrationUnavailable`, а UI оставляет ручную группировку.

## Незавершённая работа

M6 завершён и проверен, но не закоммичен. Незавершённой реализации внутри M6 не осталось. M7 ещё не начат: серверный таймер, дедупликация в памяти, истечение, клиентский отсчёт, звук и reconnect не реализованы.

При реализации M9 нужно удалить записи `command_deduplication`, которые могут связать сотрудника с карточкой, одновременно с удалением `card_authors` при `anonymousCards=true`. При `anonymousVotes=true` нужно физически удалить индивидуальные голоса и версии `personal_ballots`, сохранив суммы. Эти требования записаны в M9.3.
