# Подключение внутреннего ИИ

Спецификация описывает предложения группировки. Саммаризация пока не реализована. Вторая часть документа задаёт предлагаемый контракт приложения для отдельной задачи. Корпоративный транспорт для обоих действий нужно подтвердить у владельца внутреннего ИИ. [Спецификация группировки](Retro_Spec.md#5-группировка-и-внутренний-ии) и [задача P2.2](tasks.md#этап-p2-корпоративные-интеграции).

## Существующий порт группировки

Контракт находится в [GroupingContracts.cs](../src/Application/GroupingContracts.cs).

| Часть контракта | Что передаёт |
| --- | --- |
| `IGroupSuggestionProvider.IsAvailable` | Доступность функции в текущей конфигурации. |
| `SuggestGroupsAsync(GroupSuggestionRequest request, CancellationToken cancellationToken)` | Возвращает список `SuggestedGroup`. Запрос содержит ID и названия колонок, ID, колонку и текст карточек вне групп. |
| `SuggestedGroup` | Название группы, ID целевой колонки и ID её карточек. Одну карточку можно включить только в одну группу. Допускается пустой ответ. |

[GroupingService](../src/Application/GroupingService.cs) собирает запрос только по команде фасилитатора в фазе `Group`. Он обращается к провайдеру вне транзакции, проверяет ответ правилами доски и сохраняет предложение для предпросмотра. Применение отдельно проверяет фазу, права и `BoardVersion`. [Локальная заглушка](../src/Infrastructure/Integrations/StubGroupSuggestionProvider.cs) работает без сети. `Integrations__Ai__Enabled` сейчас включает именно эту заглушку, а `integrations.ai` отражает доступность группировки в снимке встречи.

## Предлагаемый порт саммаризации

Первый сценарий для согласования: фасилитатор во время `Discuss` запрашивает предпросмотр краткого итога всей встречи. Ответ показывается ему для чтения и проверки. Сохранение как решения, публикация или добавление в PDF потребуют явного действия и отдельного требования.

Предлагаемые имена и форма контракта внутри `Application`:

```csharp
public sealed record SummaryTopic(
    string Title,
    IReadOnlyList<string> Cards,
    IReadOnlyList<string> Comments,
    IReadOnlyList<string> Decisions,
    IReadOnlyList<string> ActionSummaries);

public sealed record MeetingSummaryRequest(IReadOnlyList<SummaryTopic> Topics);
public sealed record GeneratedMeetingSummary(string Text);

public interface IMeetingSummaryProvider
{
    bool IsAvailable { get; }
    Task<GeneratedMeetingSummary> SummarizeAsync(
        MeetingSummaryRequest request,
        CancellationToken cancellationToken);
}
```

- В `Application` добавить сценарий предпросмотра. Через [MeetingAccessService](../src/Application/MeetingAccessService.cs) проверить действующее членство, роль фасилитатора и фазу. Собрать вход из персонально разрешённых данных. Передавать только текст, нужный для сводки. Авторы, идентификаторы сотрудников, назначения, индивидуальные голоса, ссылки приглашений и данные аутентификации в модель не передаются. Одиночную карточку передавать один раз.
- Вызвать провайдер вне транзакции с ограничением размера входа и выхода, таймаутом и отменой. Проверить непустой текст ответа и согласованный лимит длины. Показывать его как обычный текст. Сопоставить результат с версией снимка. При смене фазы, прав или версии отклонить устаревший результат и предложить повторить запрос.
- Добавить отдельный DTO предпросмотра и отдельный признак доступности саммаризации в снимке. Признак группировки `integrations.ai` продолжает управлять своей кнопкой. При сбое саммаризации обсуждение и ручная запись итогов остаются доступны.

## Как подключить провайдер

1. Получить адрес внутреннего сервиса, список разрешённых адресов, модель, правила авторизации, лимиты, формат результата и тестовый контур. Для группировки в спецификации указан внутренний OpenAI-совместимый endpoint с chat completions. Для саммаризации согласовать использование того же транспорта. Названия конфигурации нового адаптера зафиксировать после получения контракта.
2. Реализовать клиент и преобразования запроса и ответа в `Infrastructure/Integrations`. Если транспорт общий, использовать его из двух адаптеров. Регистрировать реализации через [Program.cs](../src/Api/Program.cs). Текущую заглушку оставлять только в `Development` и `Testing`.
3. Разрешать вызовы только по внутренним адресам из конфигурации сервера. Секрет передавать из внешней конфигурации. При отсутствии конфигурации выключать соответствующее действие, сохраняя ручную работу и readiness. Не писать тексты запроса и ответа в журналы.
4. Проверить корректный ответ, таймаут, отмену, неверный формат, отключённый адаптер и изменение встречи во время запроса. Для группировки сохранить проверки [GroupingApiTests](../tests/Api.Tests/GroupingApiTests.cs). Для саммаризации добавить проверки прав, персональной видимости и отсутствия изменения доски при ошибке.
